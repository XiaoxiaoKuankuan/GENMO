Stage1：保留地板街舞和高难度动作的二分类规则
===========================================

此规则用于重新整理 BUMI Stage1 训练输入，只给出 ``PASS`` 或 ``REJECT``。
规则初版仅完成代码与合成回归。随后用户授权按同一规则实际复筛音乐与文本，
执行结果见 ``dance_binary_rescreen_20261030.rst``：共724518条现成机器人动作PASS，
用于替换本地SuperMimic动作参考库。现有GENMO Stage1/Stage2训练数据及权重不切换。

配置为 ``configs/bumi/quality_filter_dance_binary_30hz_v1.yaml``，
``decision_policy: preserve_dance_binary``。它独立包含资产契约和参数，
不依赖另一份配置的隐式继承。原配置及命令行默认值保持不变，用于复现历史数据；
后续使用新规则必须显式传入这份配置。

最终判定
--------

一条动作满足输入契约且没有下列明确错误即为 PASS。不是只收普通站立舞蹈，
也不把旧 REVIEW 全部改成 REJECT。

* REJECT：文件不可读、关键字段缺失、形状/帧率/具名关节映射错误、非有限数值。
  原30Hz、21关节、wxyz和米制Z-up契约保持不变；动作至少4帧。
* REJECT：UMR ``frame_ids`` 不连续、缺帧或与载荷长度不符；机器人资产、来源身份、
  坐标契约不匹配。格式适配沿用已有入口，不猜测缺失名称或偷偷改变采样率。
* REJECT：四元数不合法。现有范数误差上限为0.001；不通过自动归一化掩盖损坏输入。
  相邻 ``q`` 与 ``-q`` 表示同一姿态，不作为快速旋转或错误判据。
* REJECT：任一关节超出具名机器人机械位置范围超过0.0001rad。
  这是重定向后机器人关节的可用范围，不因舞蹈难度而改限位或裁平轨迹。
  接近限位的提示不拒绝。
* 音乐/WAV/EDGE35配对、长度覆盖及来源校验继续由原发布器和训练reader执行。
  筛选PASS不绕过这些校验；音乐不配对的数据不能发布为正式音乐训练样本。

文件/资产清单本身错误会使入口报错，不能把一个未完成的批次伪造为逐条筛选结果。
动作错误在原逐条边界记录为REJECT，并写明原因。

明确保留的动作
--------------

地板街舞、卧姿、手撑、倒立、深蹲、身体大倾斜、腾空跳跃、快速转身及快速关节动作，
不因动作风格本身被拒绝。不会按舞种、文件名或“难度”标签建立黑名单。

以下量继续计算，但只记录为诊断：

* 根高度最小值/分位数/最大值，包括原来的-0.02至2.1m高度区间之外。
* 根倾角中位数、P95、最大值和超过45度的比例。
* 肩/上肢/根高度组合形成的地板帧比例、最长连续地板段和低根高度段。
* 关节速度、加速度、jerk，根线速度和角速度的峰值、P95及超阈比例。
* 文件自带速度与差分重算速度的误差、四元数换号次数、靠近关节限位的程度。

配置中保留旧统计分档，便于以后比较；``review_*``、``reject_*`` 等旧字段名仅用于
计算这些诊断，二分类模式中不具有拒绝作用。没有把未标定的速度峰值当作机器人硬件极限。

``reason_codes`` 仅表示真正的拒绝原因；风格/速度触发项写入 ``diagnostic_codes``，
不是第三种状态。合法动作的 ``valid_intervals`` 固定为完整 ``[0,T)``，
不再用地板mask及其前后halo裁掉片段；REJECT的有效区间为空。
``floor_intervals`` 仅用于定位，不参与训练白名单决定。

输入必须回到全量动作
------------------

新的 UMR 流程不能再先取“脚底高度最平稳70%”，否则地板和高难动作仍可能在本规则之前丢失。
应从原始完整 UMR 输出目录建立显式清单，而不是从旧PASS训练集、best70%目录或其软链接子集出发。
脚本检查清单覆盖 ``--input-root`` 下全部 ``*_bumi3.npz`` 文件；它不能证明一个人为复制的
子目录就是上游全集，准备数据时仍须核对生产记录。后续实际执行已回到原完整源目录。

全量清单沿用原结构，无需脚底评分或排名：

.. code-block:: json

   {
     "n": 1,
     "files": ["aistpp__example_bumi3.npz"],
     "paths": ["/完整UMR目录/aistpp__example_bumi3.npz"],
     "clips": [{"dataset": "aistpp", "file": "aistpp__example_bumi3.npz"}]
   }

上例只是结构示意，不是实际筛选结果。自建库仍通过已有 ``--mine-root`` 入口接入。
robot_retargeter输入沿用其全量release及逐条sidecar合同，不套用UMR清单格式。

后续使用方式
------------------------

在原筛选命令中显式设置：

.. code-block:: text

   --config configs/bumi/quality_filter_dance_binary_30hz_v1.yaml
   --input-format umr-qpos
   --input-root <原始全量UMR目录>
   --selection-manifest <全量清单.json>
   --output-dir <全新二分类报告目录>

其余robot-xml、retarget-config、kinematics、mine-root等资产参数沿用已核验来源。
这里只展示参数，不提供会意外执行筛选的现成生产命令。
发布器随后也必须显式使用同一份 ``--quality-config``，配置SHA必须与报告一致。

新报告包括 ``quality_report.jsonl/csv``、``quality_summary.json``、
配置快照、``strict_pass.txt`` 和 ``strict_reject.txt``。
不产生 ``review_candidates.jsonl`` 或 ``without_joint_limit_review.txt``；
去除关节限位的反事实统计仅作为诊断，不改变正式PASS白名单。
必须使用新目录，不能将二分类报告混入旧三态报告。

验证及局限
----------

CPU回归使用临时合成动作，不对真实库做试筛。覆盖地板、倒立、深蹲、跳跃、快转、
快速关节/根移动的PASS，以及机械越限、坏四元数、NaN/Inf、错误帧号和名称的拒绝；
还覆盖完整时间线、无REVIEW报告、全量清单和地板动作发布后被真实训练reader接受。
旧配置仍按原三态规则运行，不改写旧筛选结论。

本规则把“明确的数据/运动学错误”与“风格或高动态”分开。它没有通过无依据的峰值阈值
区分每一种重定向尖峰和真实高难动作，也没有检测网格碰撞、验证力矩上限或机器人跟踪能力。
因此，PASS表示符合这套数据契约和关节位置范围，不等于已通过控制器或实机验证。
实际复筛数量另见执行报告；它们仍不构成新模型训练或物理跟踪效果结论。

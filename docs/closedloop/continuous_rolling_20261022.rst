=================================

范围与实现
----------

GENMO基线ed0fdfb、GMT基线ef5f15e；两仓库均建立feature/bumi-continuous-rolling。
本地目录为 /home/weili/bumi-closedloop-worktrees/rolling/{GENMO,legged_lab_gmt}；
服务器目录为 /home/user/liwei/continuous-rolling/{GENMO,legged_lab_gmt}。
正式两个基线分支、源码、checkpoint均未修改；本次不启动长期训练。

新配置stage2_continuous_rolling.yaml保留Stage1 s595000、60帧30Hz、15+4+1扩散、
逐步坐标平均PPO、全部16层Transformer、分组学习率、BC关闭、v3奖励、20秒随机运动
片段及原非对称Critic。只改生成调度和与之直接相关的参考、预算、来源、时间接口。

调度采用600Hz因果离散事件模拟：请求时冻结当时真实历史；DeploymentClock复用
当前同资产/同Gaussian核的单请求实测延迟profile；期间GMT所有50Hz控制和每控制
四个200Hz PhysX子步均真实执行旧参考；到达后在控制边界原子提交，并在下一0.1秒
30/50Hz公共格读取最新状态。0.1秒是最小合法网格，不是固定0.3秒周期。

边界：这是训练仿真的延迟事件调度，不是已验收的操作系统墙钟实时并发服务。
GPU合批生成可先求出不可见候选，候选只在模拟到达时发布；不会跳过等待区间的
物理控制或利用未来实际状态。未将训练GPU批量耗时冒充单机器人部署延迟，也未证明
实机50Hz实时算力。旧profile实测范围约0.248～0.275秒，公平对照使用同一分布。

参考仍只有一条绝对时间轴，没有Motion执行队列。read_watermark保留读过的最远
未来，但滚动模式的保护边界取已执行中心及右侧差分/插值支持。前缀由预计提交时间
和支持依赖计算，最少6帧最多30帧；首次使用已有profile预算，之后只使用最近8次
已完成延迟加40ms裕量，超过预算的票据仍拒绝，历史随checkpoint保存恢复。

prepare从源qpos重算原30→50Hz插值、FK、线/角速度；公共部分按原1e-5/1e-4
容差核验并精确保留。额外检查第一个自由源帧邻域的全身位姿和速度变化；不增加混合
窗口、不修饰生成动作。阈值是初始工程候选，不是经过长期物理证明的安全界限。
每环境最多一份prepared候选。CPU/GPU参考由原事务发布机制在控制边界一致更新。

物理与学习时间
--------------

每条transition保存真实executed_control_steps，奖励按真实50Hz区间唯一归属。
原returns.py已是半马尔可夫GAE：gamma_low=gamma_upper**(1/25)，lambda同理，
每条转移用实际控制步数取幂；0.5秒仅是折扣标定单位，不再约束决策间隔。
没有按plan重新分配奖励；前瞻影响、直接执行和跨时间动力学不是同一因果关系。
Critic输入、结构、价值目标和PPO概率公式不变。

8秒世界的理论容量由每环境16条改为最多80条；实际采用真实manifest条数，无补齐。
公共边界为5个控制步，保持健康episode、音乐和权威参考；边界截断GAE并自举，
在途未提交候选丢弃，不跨Actor版本携带采样链；已提交旧参考可继续被新窗口消费。
恢复仍重建PhysX，不伪恢复物理中途状态。

首次跨窗口试验发现预热25步请求的预付余量错误缩至5步，已修正：世界仍严格400步，
只为最大25步请求保留预占，结算退还未执行部分。失败记录保留，成功重试结果另记。

冻结Stage1物理对照
------------------

同8首train音乐×2个种子，共16任务；每任务执行完整可用片段、最多20秒。
部分音乐短于20秒，两模式均执行266.28秒、13314个50Hz控制，所有任务保留。
随机15+4+1链和原噪声协议相同，无Actor或Critic优化。不是泛化或长期强化学习证明。

* 固定2Hz：536次生成，530次提交，520份新源Motion直接进入中心。
* 滚动：896次生成，876次提交，872份新源Motion直接进入中心。
* 多出的未提交包括任务末尾未完成请求；滚动另外4次因全身姿态拼接单步变化超过
  0.35rad初始阈值被拒绝，继续旧参考，未增加物理失败。
* 两模式物理失败均为0/16。每秒回报2.415699→2.436250，约+0.85%；9/16任务
  每秒回报提高，其余未提高，不宣称稳定全面收益。
* 实际活动度1.072031→1.062271rad/s，约-0.91%。

时间与消费：

* 平均生成间隔0.5→0.3秒，有效频率2→3.333Hz；测试也覆盖0.1/0.4/0.7秒间隔。
* 生成完成到新生成源进入GMT窗口：平均111.6ms→同一控制边界0ms。此0ms是已量化
  到50Hz边界的事件时间差，不代表墙钟计算/传输耗时为零。
* 状态采样到新源进入中心：580→378.44ms；滚动范围340～380ms。
* 每份Motion直接中心消费源帧中位数15→9；滚动最大18帧是后继拒绝时旧参考继续执行，
  不把所有60帧说成已执行，也不把未直接消费帧说成无因果影响。
* 源权重执行时长中位数0.5→0.3秒；统计保留末尾0消费计划。
* 递归前缀来源未解析权重为0；位置/关节记录30→50Hz相邻帧与插值权重；线速度另
  记录±25/s的50Hz邻点差分源支持，角速度/FK身体速度仅共享非线性依赖支持。
* 所有成功提交已保护参考的位置/姿态和速度最大重算差异均为0。

验证与证据
----------

GENMO最终集成163项CPU通过；GMT显式使用现有Isaac FK合同的58项CPU通过，服务器
8卡各2项GPU参考缓存测试退出0。GMT复跑时曾遗漏配套GENMO的PYTHONPATH、随后
默认FK路径缺失导致跳过；指定实际依赖路径后58项全部执行，没有用跳过代替验收。

跨窗口重试为8卡×4环境连续两个8秒窗口，退出0。第一个窗口768条、第二个823条
真实链，总计1591条；所有rank分别推进[0,400]和[400,800]控制步。32个物理episode
跨窗口延续，640个控制步的中心参考仍包含上一窗口原生成源；递归来源未解析权重为0。
Actor/Critic更新均为0，behavior_version唯一为0，所有随机步0～18的零更新概率重算
最大差约9.095e-13；第19步按冻结确定性映射检查，没有纳入高斯密度。

跨窗口真实Actor转移共23295个控制步，其奖励时刻都早于各自新源第一次直接进入中心。
原因是本次生成周期约0.3秒、直接中心延迟约0.38秒。这不等于没有前瞻影响，亦不等于
所有奖励错误：新动作的中心执行收益会落到后继转移，GAE通过实际物理折扣传播。
但它确认了信用分配仍有延迟，不能以本次调度改动声称Critic价值问题已经解决。
没有按提交时刻伪标已执行，也没有把下一个Actor版本的旧行为链混入PPO批次。

完整MC采集的生成次数预占也改用模式对应网格，并与常规评估共用同一计算函数，
防止旧2Hz额度截断滚动MC。MC监督定义不变，非整网格音乐尾段测试通过。
本轮未执行Actor优化或新调度下的完整MC预热；正式规模有限采集结果另记。长期RL收益、
末端失败前价值准确性和操作系统实时并发均未在此次冻结生成器验收中证明。

--------

  cd /home/user/liwei/continuous-rolling/GENMO
  bash scripts/train_stage10_8gpu_server1.sh \
    --config configs/closedloop/rolling_stage1_rolling_validation.yaml \
    --output-dir /data1/user/liwei/GENMO_outputs/closedloop_stage10/rolling_eval_NEW \
    --evaluate-only

  cd /home/user/liwei/continuous-rolling/GENMO
  bash scripts/train_stage10_8gpu_server1.sh \
    --config configs/closedloop/stage2_continuous_rolling.yaml \
    --output-dir /data1/user/liwei/GENMO_outputs/closedloop_stage10/stage2_rolling_NEW \

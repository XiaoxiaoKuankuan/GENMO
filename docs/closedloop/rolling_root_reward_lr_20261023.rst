连续滚动：根部奖励 v4 与学习率倍率验证
====================================

本文记录 2026-10-23 用户限定两小时内的修改、真实数据试验及证据边界。
奖励重评分、固定行为数据上的参数更新、同噪声参考变化、PhysX 跟踪收益分别说明，
不能互相替代。本轮仅在已有 continuous-rolling 实验分支开发，不修改运行中源码。

修改范围
--------

* GENMO：``feature/bumi-continuous-rolling``，本地 ``rolling/GENMO``。
* GMT：相同实验分支，代码、权重、控制时钟及物理协议均未修改。
* 原固定 ``feature/bumi-music-closedloop`` / ``feature/bumi-frozen-gmt-backend`` 工作目录保留。
* 新奖励版本：``stage2.gmt8_reward_std.v4``。
* 仅修改训练评分的 anchor_pos std 0.20→0.30、anchor_ori std 0.30→0.40。
  其他六项、八项归一化权重、track_weight=2.5、GMT source_std 保持原值。
* ``rewards.py`` 显式注册 v3/v4 尺度并拒绝版本混用；CPU、向量和列式评分复用相同解析。
  ``evaluation.py`` 接受新版本评分证据；旧 v2/v3 配置仍按原公式计算。
* ``actor_optimizer.py`` 移除无实验依据的 1e-5 固定硬上限；候选仍要求有限正 LR，
  受显式最大 LR、分组倍率、原 KL、目标审计、数值检查与原子回滚控制。
* 全部 16 层 Transformer 可训练，BC 关闭，逐步坐标平均 PPO、真实噪声及已知前缀不改。

--------------------

使用正式旧运行第 50 轮固定评估保留的 104450 个实际 GMT 控制时刻。
同一份平方误差仅重新计算 ``exp(-squared_error / reward_std**2)``，没有再次平方。

根位置评分低于 0.001 的比例    15.8870%         10.9718%
根姿态平均评分                0.423710         0.505180

其余六项评分完全一致。0.5 米位置误差的评分由 0.00193045 变为 0.0621765；
1 米位置误差的新评分仍只有 0.0000149453，因此大漂移的评分饱和并没有全部消除。
这些数值只说明新公式改善了部分误差范围的可区分性，不是机器人运动已经改善。
离线工具的慢衰减 C 曲线没有进入训练。

参考消费与输出探针
------------------

原 case 含 357848 个实际 50Hz 控制时刻。按真实 plan、绝对参考时刻与相邻源帧
插值支持递归追溯继承前缀，无缺失来源。24538 个计划中，23032 个前缀为 11 帧，
1506 个为 10 帧；直接中心消费的新源帧数中位数 9，均值 8.2865，最大 36。
每计划的中心支持权重折算持续时间中位数 0.3 秒，均值 0.27515 秒，最大 1.2 秒。
这是当前保留时段的统计，零消费或右截断不自动意味着未来永不消费。

候选探针固定相同条件、初始状态和真实 innovation，重走四个训练步骤及冻结末步。
普通探针为候选间相同的 32 条链，另加各候选真实高 KL/高 ratio 尾部。
公平数值比较使用共同普通探针；中心关节变化先按原 30→50Hz 插值权重合成向量，
再计算 RMS。缺失任一生成源的探针就不覆盖，不假设其变化为零。
这种测量是旧真实消费位置上的反事实参考变化，不是新策略的机器人真实运动。

测试与计算边界
--------------

首批 104 项回归通过，新增分块及概率/梯度/回滚关联回归在服务器隔离源码中
58 项通过；两批有重叠，不累加宣称唯一测试数。分块不改变全局 PPO 分母，
只限制条件反向图生命周期，默认正式路径不启用此单卡实验选项。

第一次无条件图分块的单卡整批重放，在零更新阶段发生 CUDA 非法访问，尚未
执行候选 Adam，不能归因于大 LR。增加显式分块后的重算通过；初次故障的底层
根因尚未通过独立算子复现定位，不能把规模相关推测写成已证明原因。

临时重放源码、测试模型、日志和缓存使用本任务精确的 /tmp 路径；结果数值进入本文
及记录文本后清理，不覆盖或清理原正式 checkpoint、训练日志、case 与数据集。

  这些检查是现有优化约束，不是已证明的物理安全边界。
* 三候选接受后的active clip均为0，PPO梯度范数均为0.218488，梯度裁剪系数均为1。

  所有模块的FP32更新舍入为零比例依次只有0.004608%、0.001814%、0.001453%。

结论和未完成的物理证据
----------------------

新奖励、10/50倍LR测试、触发后的10步实现与有限比较已经完成。大LR没有被静默忽略，
实际是候选更新造成KL超限，部分还使整批目标下降，然后按原逻辑回溯。接受后参数与
参考确实变化，但近期腿参考仍小；10步在当前同数据对照中没有改善这个现象。

不建议据此直接把50倍或10步作为正式默认。四步主配置保留原基础LR1e-6，10步是独立
可测试配置。v4需要新奖励下的真实采集/价值更新后评估，10步正式物理使用还需相应
真实核的部署延迟标定。不能绕过这些数据一致性要求，或把旧v3优势重新标成v4。

本次只有单次更新和反事实生成参考比较，未证明机器人跟踪改善，也不能断言增加
去噪步数对长期学习一定无效。下一步应先用v4采集同协议数据、评估实际接受LR约
2.5e-6的四步连续更新，再检查同组任务的腿/身体误差与失败；10步暂保留对照。
服务器正在运行的旧正式任务继续使用原v3/四步配置，本轮没有自动开启新长期训练。

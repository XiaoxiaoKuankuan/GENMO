# Stage10 Actor 重构、去噪步抽样与四档真实闭环验收

本报告记录 2026-10-10 在服务器 1 八张 GPU 上的实际代码修改和有限验收。
维护分支为 GENMO `feature/bumi-music-closedloop`、GMT `feature/bumi-frozen-gmt-backend`。
开发使用 detached worktree，原功能分支中用户未提交的 Stage1 评估和 Isaac 播放改动不属于本次修改。
没有在本地运行测试，没有增加环境数，没有启动长期训练。

## 结论和适用范围

- 编译 FP32 路径完成 1024、2048、4096、8192 条真实转移各两轮训练，实际 Actor 更新分别为每轮 2、2、4、8 次；无 KL 提前停止，所有有效链均参与更新。
- 1024 条另有实际停止进程、加载完整断点、重建环境后继续第二轮的验收。恢复重新建立物理 episode，保留模型、优化器、采样/RNG 和资源消耗；不声称恢复了未保存的物理世界。
- 每环境仍为 64 个活动环境/卡，四档只改变每环境决策次数为 2/4/8/16。八卡全局是 512 个环境，不复制数据填充有效样本。
- Actor 采用 microbatch 128，KL 采用 256，CFG 合批；内部固定形状网络块容量 64 与训练 microbatch 是不同概念。
- 独立 4/8 步 PPO 实验在 1024 条真实数据规模通过两轮闭环，行为生成和最终 KL 均保持全部 20 步。
- 当前 TF32、BF16、融合 efficient attention 候选不进入默认训练路径；各自失败原因和原始报告保留。
- 两轮固定任务奖励的差异不足以证明学习收益或确定最优规模。保守规模建议为 2048 条完整 20 步；1024 条/8 步保留为下一阶段效果对照。8192 的吞吐收益很小，暂不选为默认正式规模。

## 本次继续修改的代码

基础联合 GEMM、批量条件编码和编译执行接口在本次基线中已经存在；本次继续修复、减少重复工作并完成真实验证，不将已有代码全部算作新增实现。

## 剩余瓶颈、证据与背压

8192第二轮 Actor285.99秒、最终KL49.36秒；它们是实测量，不代表已经达到可接受的性能目标。
本轮每卡PPO40960个内部转移，microbatch128对应320个前反向，最终KL80个256批前向。
基础块预测仅用于核对工作量，不能掩盖采样外围和归档成本。

同轮rank0的世界RPC累计133.214秒，GMT神经网络推理约0.665秒，物理控制段11.978秒，
其中PhysX step4.947秒；奖励Python消费18.422秒，生成最大rank60.286秒。
这些是嵌套时间，不能直接相加。世界RPC包含后端执行、证据/传输和管理，不能把133秒全部称为网络延迟。
梯度通信rank0约1.653秒（不含打包/拷贝），采集同步等待最大rank30.367秒；等待已经包含在采集墙钟中。
因此后续仍应优先优化证据/奖励消费和大矩阵反向，GMT网络推理本身不是主要瓶颈。

真实65.96MB世界回复的八rank独立CPU通路对照，逐字段/字节一致：rank0的RPC解码
0.432→0.165秒、只读trace建立0.880→0.033秒；但“展开并完整深拷贝消费”2.194→2.621秒。
惰性视图将部分工作后移，**没有证明完整消费整体提速**，仍需进一步列式奖励处理。
64条参考窗口发布独立P50约9.38～9.87ms→2.05～2.12ms，不将这一局部倍数称为整轮采样倍数。

8192两轮执行证据后台归档分别529.947和516.064秒，包含压缩及重新读取校验；正常训练阶段可以重叠，
但本次退出仍等待199.149秒排空。队列上限4，满时背压机制保留。两轮未发生持续增长，
但不能据此声称已完成500轮存储稳态验收，也不能把退出排空从总成本中隐藏。

K8真实两轮期间采样监测最大整卡显存55599MiB（GENMO/GMT/PhysX上下文合计）；这是离散查询观察峰值，
不是瞬时峰值。8192 Torch allocator约45.34GB只覆盖该进程，不能替代整卡统计。
更大的microbatch能否提速须单独实测；本次正式有限闭环采用128/256，不宣称256/512已最优。

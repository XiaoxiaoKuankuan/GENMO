第二阶段随机时间与运动初态修复（2026-10-16）
================================================

本次解决什么
------------

旧配置关闭了普通Actor采集的随机起点。虽然正常物理episode可以跨4秒rollout继续，
但后段必须等机器人先执行完前段才能进入训练；已有500轮记录中FineDance的实际
时间位置覆盖仅79.6309%，047长251.4秒、累计最远49.8秒。仅打开random_start只会
移动音乐和活动度目标，机器人仍从站立开始，不能补齐对应的运动状态。

本次同时修复音乐起点、配对运动状态和跨环境重复抽样。代码落在GENMO的
feature/bumi-music-closedloop与GMT的feature/bumi-frozen-gmt-backend；未把另一项
工作的feature/stage2-asymmetric-denoising或feature/stage2-tracking-history合入。
开发中检测到工作区被其他会话切换，先在临时源码副本完成实现和验证；两边新分支
提交已推送且工作区干净后，按用户原指令切回上述原分支集成。

如何抽取时间
------------

``stage10.dataset`` 当前设置::

    random_start: true
    sampling_contract: rank_shared_time_bins.v1
    time_bin_seconds: 1.0
    standing_start_probability: 0.2
    initialization: paired_motion_warmup.v1

先按原20/35/25/20任务概率抽来源。运动初始化任务把该来源全部样本的合法起点
按1秒划分bin，使用共同种子打乱后给8个rank分配互不重叠的固定分片。同rank所有
环境共享一个无放回游标；自己的分片走完才重新打乱，bin内随机选择30Hz帧。
长样本因合法时间bin更多而获得更多运动初始化机会。此规则均衡时间bin，
不等于逐帧严格等概率，也不保证来源实际控制时间等于任务概率。

最小剩余时间继续使用实际4秒world_seconds，末尾不足4秒的短样本从0开始。
047的合法随机起点现为0至247.4秒，无需先存活到该处；最后4秒可从末端合法起点
继续执行。单元测试证明8个rank合起来的一轮分片没有重复或遗漏时间bin。
某个rank提前走完自己的分片时可以进入下一轮，并非要求所有rank同步换轮。

20%的任务保留站立、音乐从0开始，用于继续覆盖真实部署的启动过程；80%的任务
使用配对运动初始化。20/80是显式可调的首版候选，不是效果消融得出的最佳比例。
共享池的分片、RNG、游标和轮数进入checkpoint，标定过程不会消耗训练采样进度。

如何补齐运动状态
----------------

假设抽到源音乐第200秒，episode的第1秒对应源音乐第200秒：

1. 核验训练清单、配对动作文件身份、完整帧数和21个关节名称；读取对应运动。
2. reset在源第199秒的姿态开始，同时写入根线速度、根角速度和关节速度。
   速度来自GMT已有参考转换和FK，保持与实际50Hz参考的差分约定一致。
3. 只去除reset帧的水平平移和yaw，保留绝对根高及后续相对运动。初始关节角沿用
   GMT第一阶段的软限位裁剪；回读证据记录裁剪数量和最大偏差，不声称逐值等于
   超限的原始角度，也不套用站立足底1毫米余量的证明。
4. 冻结GMT真实执行50个控制步、200个物理子步，以配对片段预热1秒。reset后
   本体历史只有1个真实样本，预热结束累计51次采样，最近50个有效样本进入GENMO。
   没有把数据集中的历史帧写入本体历史。
5. GENMO在episode tick=600接管，音乐和活动度目标使用同一个music_start_frame。
   起步时已承诺参考前缀来自bootstrap，保护、提交和截止规则继续生效；没有额外
   向Actor传入完整配对未来动作。距源开头不足1秒或参考越过源尾时显式保持边界姿态，
   并记录保持数量；音乐真实结束时间不延长。

后端写入后独立回读根状态、关节角和速度，GENMO还检查回执中的实际验证标志、
音乐偏移、样本和动作文件身份。验证集/测试集、评估/完整MC和部署不启用此训练reset；
非向量后端收到运动reset会明确拒绝，不会静默回到站立。

如何看覆盖
----------

每轮collection.json新增两类统计：

* time_sampling记录已发出的站立/运动任务数、来源时间bin总数、rank分片大小、
  已完成轮数和当前游标。它只表示抽到了哪些分段，不代表执行成功。
* sampling_coverage将同rank各环境真实Actor控制区间求并集，记录实际控制步、
  上层转移、样本数、完整样本数和时间覆盖。源时长按num_frames/30秒计算，
  完整样本判定允许50Hz离散结束产生的小于1个控制步的尾部余量（11个600Hz tick）。
  不计预热、MC、BC，不重复累计同一时间区间。

当前在线覆盖是rank内并集。全局唯一覆盖应继续合并checkpoint中的8个rank区间，
不能直接相加8个百分比。新采样让后段可直接到达，不能承诺有限训练预算下100%
实际覆盖；难动作仍可能在预热或Actor接管后失败，应结合实际覆盖与失败数判断。

已执行的验证
------------

GENMO相关回归247项通过，GMT相关回归72项通过（包括5项真实MuJoCo后端回归）。
覆盖共享时间bin、精确恢复、
标定隔离、音乐与运动偏移、实际回执拒绝、参考保护、关节映射、邻居隔离、配置拒绝、
活动度与采集/价值计算边界。GENMO保留一条既有autocast弃用提醒。GMT首轮有一项
CUDA单测因未设置LOCAL_RANK而失败，补齐测试运行环境后67项通过，没有放宽断言。

服务器1真实单GPU双环境验证使用冻结GMT140500、50Hz控制/200Hz物理：

* FineDance 047：50、120、200、240秒。
* FineDance 051：90秒。
* Mine dance_2__badboy：40秒。

6个案例均完成姿态/速度回读核验与50步实际预热；重置目标环境时，邻居的根/关节
状态、时钟、GMT历史和GENMO历史均保持。初态根/关节速度确实非零。6个案例的
软限位裁剪数分别为2/0/2/3/3/1，最大裁剪约0.113rad，已明确记录。

随后在服务器1执行8rank、每rank 2环境、连续2个4秒窗口的真实collect-only验证。
Stage1 s595000生成动作，GMT140500负责控制，启用完整物理证据：

* 第一窗口96条上层转移、2400个Actor控制步；第二窗口122条、3021步。
  合计218条、5421步，即108.42秒Actor物理控制数据，不含950步预热。
* 两个窗口合计25600个分配物理子步；其中Actor控制对应21684步。
  已确认GMT控制共6371步，和占用的全部6400个环境控制槽分别统计。
* 共发出19个任务：16个运动初态、3个站立；18个已进入Actor采集，另1个仍处于
  最后窗口的预热阶段。预热物理失败0，Actor采集中物理失败0。
* 16个初始episode跨窗口连续执行，3次正常music_end，未因4秒rollout边界重置。
  FineDance 003从163.4秒实际执行至170.4秒，018从150.3至157.3秒；
  Mine shake-it-nutuan4从160.433至167.433秒，直接证实中后段进入普通Actor采集。
* 两轮全部随机链的零更新概率重算通过，最大绝对log概率差和ratio-1均约9.095e-13。
  Actor更新0、Critic更新0、优化器尝试0，源码冻结与世界关闭检查通过。

上述验证证明采样、运动reset、真实历史、GENMO接管和连续采集链路可运行。
它没有训练新Actor，不能证明奖励/舞蹈质量提升，也没有验证长期覆盖达到100%。
仍需用新运行的覆盖曲线和固定相同任务的评估比较模型效果。

运行与恢复边界
--------------

本修订改变了初始状态分布和采样身份；旧500轮checkpoint不能作为等价断点恢复。
配置继续从s595000初始化，新运行目录中的完整MC门禁会重新预热Critic，旧预热
artifact已从默认配置解除绑定。历史模型、旧run和数据都保留。原奖励、PPO目标、
学习率、Critic结构和正式训练规模不在本次修改范围内；未启动新一轮长期训练。

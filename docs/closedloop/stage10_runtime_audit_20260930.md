## 已确认的重复工作和可保持数学语义的优化方向

1. `policy.transition_parameters()`每个去噪步重新校验条件、运行50帧history GRU及
   prefix/music编码。同一采样链条件不变，20步重复编码；原Stage1Actor.sample已把
   编码移出循环。无梯度采样/概率检查/固定候选KL可缓存，有梯度阶段不能简单detach。
2. 每轮64×20=1280个内部去噪transition，CFG2.5分别计算条件和无条件两分支。
   采集2560次denoiser前向、概率检查2560、PPO2560加反向、三候选KL7680、
   最终KL2560，合计至少17920次前向，另加BC。完整额外审计/三候选/最终再检
   是当前实现的校准与保障成本，不能全称DPPO必需的数学工作。
3. 概率检查仍串行在rank0重算。可以保持全部样本和全部去噪步覆盖，分给八卡。
   去噪microbatch当前固定1，逐步bool/float触发同步；批处理和CFG分支合批值得验证。
4. Critic只有246017参数、18个参数张量，80步使用约1600次细粒度all-reduce与
   80次索引广播。可以合并梯度bucket，保留80步设置。采集已计算旧/下一价值，
   fixed_targets又重复计算一次，也可在保持固定价值契约的前提下复用。
5. 每次RPC回复先为磁盘预留估算完整JSON编码一次，再为正式journal重复编码。
   136条advance原回复四种长度各抽一条、每条两次CPU微基准，按频次加权粗估
   双编码约22.9秒，两次重复敏感性17.2～28.6秒；这是独立基准外推，不是原轮
   直接计时或置信区间。排除SQLite/fsync/RPC/奖励/物理耗时。复用单次编码有实际依据，
   必须保持持久化成功后才ACK，不能削弱真实执行证据。
6. 每轮三候选含全模型/Adam/梯度CPU快照、恢复、FP64变化和ULP统计，各卡重复执行；
   每阶段还做全模型指纹。可优化数据搬运/统计组织，但需保留一致性与KL门槛。
7. 每阶段再次写读完整rollout共享文件，保存后同步gzip+完整解压核验。可改进分发和
   归档实现；不应直接删除归档验证或悄悄降低日志完整性。

优先顺序：无梯度条件缓存、概率重算八卡分片、单次JSON序列化；再验证去噪微批、

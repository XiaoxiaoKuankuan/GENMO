# Stage10 大规模重构与服务器1有限验收记录

本页对应 2026-10-10 的实际实现和有限验收。**8192 条真实 rollout、计划 8 次 Actor 更新的完整轮尚未通过，不能开始正式训练，也没有可交付的普通轮总耗时或相对 Stage1 的学习收益。** 两次大规模真实采集在异步配额边界停止；没有用 160 条测试代替，也没有减少更新、放宽概率门槛或隐藏额外物理推进。

维护归属仍为 GENMO `feature/bumi-music-closedloop` 和 GMT `feature/bumi-frozen-gmt-backend`。开发、测速均使用隔离工作区，原模型、执行证据和 Stage1 未提交评估改动保留。没有启动长期训练。

## 严格回归结果

所有运行测试都在服务器1。八rank单元/协议测试和真实GPU计算块分别标识，不将 CPU 协议替身称作物理验收。

- `gradient_candidates_v3`：原真实旧 rollout、共同非空 Adam 的 B64/128 反向候选通过全部梯度、权重、Adam门槛；原概率未改写。
- `blocked64_gradients_v1`：新合同实际采样的诊断链，B64/128/256 的321个参数张量回归通过；动作未执行物理。两次更新后的 KL 为0.031598～0.031603，**包括B1参考均超过0.03，不能当作训练接受**。
- `bf16_gradients_v5`：直接 BF16 骨干失败，193个梯度张量不满足原回归，最终 KL 约2452～2461；禁止进入默认生产配置。
- `global_updates_v2`：8个不同BC随机流分别恢复，Actor/Critic/优化器/RNG精确回滚，物理/预算不退款；PPO八次参数更新和BC/Critic全局归一化对照通过。
- `numerics_unit_v5` 各48项，`scale_update_units_v1` 各37项，`evidence_pipeline_units_v1` 各67项，GMT `evidence_copy_units_v2` 各34项通过。
- GMT复制测试第一次因测试环境缺少独立GENMO源码路径失败；补齐 `PYTHONPATH` 后通过，断言和生产检查没有放宽。
- 零更新检查仍为 log-prob `1e-4`、ratio `1e-3`、独立高斯 `1e-8`；末端、置换、尾批和混合步覆盖保留。

## 基础计算块：最慢rank的 P50 / P95，单位秒

A 是64个真实不同环境条件的一次完整20步CFG生成；B 是128内部转移的PPO前向反向；C 是256内部转移KL无梯度前向。它们只重放真实条件，不代表新的物理 rollout；所有候选分别重新采样行为链，没有事后改写 old probability。

| 路径 | A：gen64 | B：fb128 | C：KL256 | 结论 |
|---|---:|---:|---:|---|
| 原 FP32 参考 | 6.5263 / 6.5265 | 2.7836 / 2.7906 | 1.4822 / 1.4849 | 参考 |
| FP32 fast v5 | 6.4812 / 6.4818 | 1.4450 / 1.4454 | 1.3660 / 1.3661 | 自身概率通过，仍慢 |
| 固定64网络行 FP32 | 4.0949 / 4.0950 | 1.1207 / 1.1238 | 0.9321 / 0.9322 | 自身概率及梯度回归通过，完整闭环待验收 |
| TF32 v5 | 10.5920 / 10.5930 | 2.4048 / 2.4055 | 2.1839 / 2.1842 | 性能退化，不采用 |
| 直接 BF16 v5 | 1.5013 / 1.5021 | 0.5216 / 0.5226 | 0.4373 / 0.4385 | 自身概率通过，但更新不通过，拒绝 |
| 补偿 BF16×3 | 3.4425 / 3.4436 | 1.0662 / 1.0688 | 0.7955 / 0.7957 | 自身概率通过，完整更新待验收 |
| 补偿 BF16×6 | 6.0194 / 6.0212 | 1.5806 / 1.5832 | 1.3133 / 1.3134 | 自身概率通过，较×3更慢 |

固定分块 FP32 相对参考：A下降约37.3%，B约59.7%，C约37.1%。这三个下降比例不能相加，也不是完整轮加速比。固定分块与原FP32同噪声20步输出最大差2.12e-5；补偿BF16×3/×6最大差分别0.00151/0.00172，明确属于不同数值合同，不宣称逐位相同。

原始任意形状编译曾有最大零更新log-prob误差0.232，已拒绝。固定形状纯denoiser编译的后续结果另行追加；不编译Python事务/RPC或文件操作。

固定分块的fb128 profiler显示，`aten::mm`自身CUDA时间约660ms，占59.6%，主要落在SIMT SGEMM；cat/mul/add也占显著时间。全模型FP64累计单独约5.70ms，FP32约1.66ms。累计器不是当前唯一瓶颈。不能把旧实现线性乘成几百秒就认定合理。

## 真实采集失败及外围瓶颈

两次目标8192的实际采集分别为 `full8192_v1` 和 `full8192_profile_v2`。第二次启用cProfile，rank0耗时371.428秒，完成1019/1024条；其他失败rank完成1017～1023条。**这个时间是失败诊断且带profiler，不是普通轮耗时。没有进入全局PPO，也没有8次实际Actor更新。**

原因是环境提前终止/音乐结束后需要真实1秒预热，各环境完成16次决策的时刻不同。已完成16次的健康环境继续参与同一个PhysX世界；如果不给它新的执行请求，尚欠决策的环境也无法独自推进。代码此时明确停止，没有偷偷冻结健康机器人或补长尾drain。

要完成这个边界，必须先确定一种明确语义：固定全局样本数并管理边界未完成动作，或保留每环境精确16条并允许如实计量必要等待执行。前者还需设计行政截断/续接/GAE，不能只把本地计数改成全局计数。本任务尚未得到改变这项约束的回答，不把任一选择擅自当作已授权。

rank0剖析约6.28亿次Python函数调用：轨迹展开约44秒、journal编码约44秒、deepcopy约31秒、RPC累计约175秒；这些为嵌套诊断计时，不直接求和。GMT推理约0.679秒，PhysX实际步进约5.300秒，后端控制路径约12.61秒。主要问题仍包含大量CPU对象处理，并非GMT网络本身就需要数百秒。

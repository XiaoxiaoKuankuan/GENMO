按递归原计划、源帧及真实插值权重映射，关节参考变化RMS分别为：

缺少任一来源时计诊断缺失，不补零；全部15973条链仍参加原PPO和KL。

冻结末步前后normalized扰动保留比例中位数分别约0.555、0.580、0.588。
更新确实传到GMT实际消费的参考支持，但绝对幅度很小；不是所有方向都固定缩至该比例。
这是旧条件、同噪声下的反事实生成参考，不是新Actor的真实机器人运动，也不代表
所有训练累计变化。root前3维仍为模型运动特征，不冒充世界XYZ。
没有将未直接中心消费帧的KL都称为无效，也没有删除它们的概率因子。

实现、失败和修复
----------------

* compare_stage2_optimizer_batches.py统一三种批量的目标感知回溯，保留显式KL-only对照；
  optimizer_direction.py和updater.py可选测量整批梯度、实际Adam增量、内积/夹角，
  恢复原小批梯度对象。正式关闭额外整批反向，避免其成本进入生产。
* training_checkpoint.py、training.py及训练CLI提供新实验完整状态继承：只允许
  有效批量及评估监视差异，不清空Adam、不改变实际核/奖励/时钟或参数映射；
  立即发布experiment_initialized恢复点。原父checkpoint只读。
* run_management.py、budget_ledger.py以新空SQLite账本的一次原子initialize事件
  继承已耗预算和接受身份，重开按事务重放；首次运行因未适配生产IncrementalBudget
  在物理采样前退出，失败日志保留，修复后两组重新开始。
* training.py有限回溯无可用Actor步时记录零更新并进入新物理采集，正常批次推进轮次；
  Actor版本与Adam计数只在真实接受更新时增加，不能用轮次冒充学习次数。
* execution_compatibility.py、evaluation_runtime.py、periodic_monitor.py、
  tensorboard_metrics.py统一物理评估协议：纯训练批量/频率仅追溯，实际奖励、核、
  时钟、任务、噪声和未知执行字段仍验证。首次4096三轮后被旧检查挡住且未到周期保存，
  没有可恢复Actor9；保留现场，从同一Actor6重跑。重跑8rank Actor/Critic指纹
  与失败前第9轮完全一致，但未宣称比对了当时未保存的Adam。
* 8192曾受控在第7轮保存后退出以加载评估修复；为避免重建episode影响公平比较，
  该现场单独保留，不混入最终连续三轮结果。
* run_stage2_training_supervisor.py对用户授权正式任务意外退出30秒后从latest恢复，
  上限累计200；显式停止信号会停止子任务并取消恢复。记录每次真实退出和恢复起点。
  没有增加ESS、回报不改善或单曲新增失败的停训门槛。
* summarize_stage2_batch_comparison.py连接真实递归消费来源与同噪声探针，
  三个batch配置分别供独立实验；正式使用stage2_batch_8192.yaml。

本说明对应 ``feature/bumi-music-closedloop``，参考 GENMO 提交

当前算法
--------

* 跟踪奖励严格使用 GMT 的八项函数：Anchor位置/姿态、身体位置/姿态/线速度/角速度、
  双脚相对高度、十二腿关节位置；权重按GMT原权重归一化，跟踪总权重2.5。
* Stability奖励权重为0，音乐奖励关闭；物理失败终止、力矩、接触、动作变化约束保留。
* 关节越界代价为0.7参考+0.3实际，按真实软/硬限位分别记录越界幅度、比例和连续时间。
  参与奖励的是已消费参考；完整60帧可修改后缀另做合法性诊断，不重复累加执行奖励。
* Actor条件不变。Critic的 ``tracking_history_encoder`` 输入为50帧×(90维状态+1维相对时间)。
  原48维本体感觉之外的42维依次为真实根部线速度3、根高1、GMT动作21、脚接触2、
  相对Anchor位置误差3、姿态误差6、历史参考线速度3、角速度3。
  历史逐50Hz真实采集，时间不晚于决策时刻；不存在未来动作、未来奖励或复制50份当前状态。
* 历史GRU复制Stage1原权重，新增42列零初始化；独立学习率1e-5。
  音乐和已承诺前缀编码冻结，原256维/2层/4头Transformer和Value Head学习率1e-4。
* 20步生成对应索引0..14冻结Stage1、15..18随机DPPO、19冻结Stage1确定性去噪。
  最后一步不加探索噪声，概率只定义在19个随机转移上；优化只覆盖中间4步。
* 普通更新对全部有效真实链计算四步KL，冻结网络检查参数/存储/版本/计算核身份。
  首轮和每100轮完整概率检查另外重算确定性末步，确实覆盖20次前向。
* 保留20%站立开头、80%随机音乐位置+配对运动预热以及跨rank时间bin采样。
  每卡128环境，4秒连续世界窗口；全局Actor/Critic批量2048，Actor/KL微批128，BC每轮1024。
* 完整MC预热为四来源各24首独立训练音乐，共96首×2种子；独立验证为16首×2个不同种子。
  从音乐开头执行到真实音乐终点或物理失败；不把10秒截断当完整MC。

本分支补齐参考实现的细节
----------------------

参考实现的严格概率检查只遍历19个随机步骤，本分支增加第20步确定性输出核对。
参考KL发布器输出v1，而普通训练要求带优化配置的v2；本分支贯通发布/加载，
将实际学习率、epoch、批量、BC、目标及软硬阈值绑定到候选证据，拒绝挪用旧实验。
Critic历史模块采用明确的新名称；Actor原模块不改名。

TensorBoard继续一个任务一个run，八类分组。新增 ``Policy/p95_trainable_kl``
和 ``Policy/chain_joint_kl``，分别看四步更新尾部和整条随机链的累计变化。
``Policy/trainable_kl`` 为四步每自由坐标均值；``Policy/max_step_kl`` 为四步中的最大均值。
联合链KL先按坐标/步骤求和，单位不同，不能直接与平均坐标阈值比较。
已关闭Stability不再画恒零曲线。历史500轮事件文件与模型不改写为本算法结果。

与参考分支的具体差异
------------------

GMT生产源码与参考3c05061相同，额外修订仅在本分支的旧CPU测试夹具与记录。
代码同步阶段GENMO的DPPO生产目录有五个文件不同：KL发布器、严格概率审计、Critic历史模块命名、
训练器中对应优化器参数名、精简TensorBoard。后续正式训练又修改运行控制和配置校验，
支持2000轮与每100轮永久保存。其余奖励、采集、随机初始化、去噪、
四步更新与KL、完整MC实现均采用同一参考代码。
独立MC复核工具另补齐真实初始化RNG及分来源误差，部署与数值验证工具保留服务器1入口。

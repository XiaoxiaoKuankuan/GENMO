整批梯度方向分析，不能由总clip比例替代归因。

已实施改进与验收层级
----------------------------

第一项是保持原数学合同的条件图分块。``chain_ppo.backward_chain_surrogate``
先按原完整minibatch与真实global N计算全量PPO系数，再按最多1024条本rank链
建立条件图；每块完成全部合同随机步骤后反传条件编码器并释放，Actor梯度跨块累加。
最后微批中可能保留条件梯度池的引用显式释放，None保留无界参考。
joint-sum、分母、随机核、跨rank SUM、统一clip、单次Adam及KL接受门槛保持原义。

23项CPU分块/边界测试及60项既有完整链/短扩散回归通过，覆盖正负优势裁剪、
masked坐标、尾块、global N大于本rank N、跨调用梯度累计、1024+1边界、条件编码一次
和图释放。小型真实CPU网络相对梯度容差不是生产GPU验收。
随后真实八卡固定case验收已通过：全局16链、5个随机步骤的独立Normal梯度检查，
全部5个微批/条件块变体最大relative L2=3.3012e-7；每rank1025链、全局8200链的
None无界与1024+1条件块对照，完整参数梯度relative L2=3.4392e-7，loss完全相同，
重算误差0，8rank参数/RNG均保持不变。GPU相对L2门槛仍为2e-5，没有放宽。
证据已复制为本地 ``A_probability_and_gradient.json``，SHA已列于输入表并实际核对。
1025与1024+1的峰allocated分别27139942400和27134515200字节（约27.14GB），
几乎相同。测量范围为backward与全rank SUM的PyTorch峰值，包含既有模型/缓存，
明确不含Adam和PhysX。该边界对照证明执行等价，不能据此宣称已实测大幅降低显存；
完整全批候选的工具峰值现已测量，见下节；正式11轮PyTorch峰值及含PhysX的设备
离散观测见文末，设备绝对峰值仍未被连续测量。
第一遍无梯度条件池、模型/Adam、全量records和PhysX仍占显存，离线工具没有物理世界，
不能仅凭工具峰值宣称正式8×128环境安全。配置容量上限10240链/rank也必须纳入判断。

集中度并绑定SHA、原manifest、epoch orders与更新前快照；它不输出参数梯度归因。

继续进入SUM；这些替身测试不能代替真实Gloo/NCCL运行。

第三项是生成提案诊断漏帧修复，提交 ``95107a6``。原诊断只接受60/120帧，导致合法30帧

的训练差主因。旧评价中的该字段应按缺测处理，不能据此否定实际执行奖励或声称动作非法。

第四项是默认关闭的显式Actor LR迁移，提交 ``675c686``。训练入口和supervisor新增
``--initialize-actor-lr``，必须配合新目录的 ``--initialize-from-checkpoint``，

``training.trust_region.maximum_lr`` 改变，前后均须两值相等且正有限。其余trust字段、
KL、奖励、采样核、Critic与优化器组倍率仍严格比较，不恢复目标单调门槛。

加载前完成identity、模型、两Adam、组名称/参数映射及BC检查，成功加载后只改变
Actor各组lr；Actor/Critic参数、Adam矩/步数、原预算、各rank RNG/collector与累计
计数继承。``explicit_checkpoint_actor_lr`` / ``actor_learning_rate_only.v1``
记录旧配置LR、旧Adam实际LR、新分组LR，不宣称整个Adam逐字节不变。
初始完整快照已经使用新LR；supervisor有latest后仅按新合同resume。原新实验的
best/monitor清理不变，刷新 ``selected_actor_lr``，历史 ``last_accepted_actor_lr``
保留。MC完成标记与校准边界继承，生产预热门槛未修改；正式初始化至第11轮的
实际产物已确认没有重复MC预热，具体运行证据见文末。

该迁移的48项新增CPU回归与31项相关既有回归共79通过；真实非空单/多组Adam除LR
逐项相同，下一次同梯度更新与手动load+setLR参考完全一致，非法差异在写入前拒绝，
新checkpoint按新合同普通resume成功、旧LR合同拒绝。另有1项既有测试因缺失
``stage2_transformer_groups.yaml`` 失败，已从HEAD原函数复现，最终针对性回归排除该项；
不能称全仓库全绿。这些是CPU恢复/入口证据，未代替八卡正式恢复和物理收益验收。

第五项是初始化快照保留待应用采样状态的恢复修复。完整checkpoint载入后，
``runtime.restore_logical`` 先保存 ``saved_logical``，首次 ``collect`` 打开预算
阶段后才应用它。旧 ``checkpoint_state`` 若在这两者之间保存
``experiment_initialized``，会记录新建空collector和初始time_pool；若随后再次
resume，源采样池及各环境游标可能丢失。不中断首次采集仍使用内存中的原pending，
因此该缺口与连续采集路径不同；原十轮连续运行、没有重启，没有证据表明此问题
造成了前十轮收益偏低，不能把它列为优化效果差的主因。

最小修复在active世界拒绝快照检查之后，若存在pending就返回其完整逻辑状态的
``copy.deepcopy``，不应用、不消耗、不删除pending，不提前创建环境或调用采样器。
首次collect、apply_restore及已应用后的正常快照路径未改，两网络、Adam、奖励、
GAE、概率和KL逻辑不变；PhysX仍按原恢复合同新建episode，并非物理状态连续恢复。

``test_runtime_pending_restore_checkpoint.py`` 新增8项CPU回归，使用真实共享
``StratifiedTimePool``、各环境 ``FullMusicSampler`` 与执行计数，经真实collect
入口在第一次物理请求前终止。一次及两次序列化/重建/恢复后，下一任务、实际音乐
数组、噪声编号和游标与不中断路径逐叶相同；另验证深拷贝无别名、不消费pending、
active拒绝及只应用一次。8项新增与27项既有恢复回归共35通过。独立CPU进程仅在
